# MyOS 用户指南

[English](getting-started.md) · [项目介绍](../README-zh.md)

本指南讲安装、日常使用、怎么教 MyOS，以及它是怎么运作的。命令和配置细节见
[参考文档](reference.md)（英文）。

## 安装

你需要 Codex 或 Claude Code、Python 3.13 和
[Poetry](https://python-poetry.org/docs/#installation)。

1. 下载并安装 MyOS：

   ```sh
   git clone https://github.com/zhoudaxia233/MyOS.git MyOS
   cd MyOS
   poetry install
   ```

2. 在 `MyOS` 文件夹里打开你的助手，对它说：*"按 docs/reference.md 把 MyOS 接到这个助手上。"*
   它会装好 MyOS 的 Skill 和工具，把你的自我模型加进助手每次会话开始都会读的指令里，
   并打开自动刷新。完成后重启助手。想自己动手的话，按
   [Connect an assistant](reference.md#connect-an-assistant) 操作。

3. 检查一下：在 `MyOS` 文件夹以外开一个新会话，问 *"MyOS 里关于我希望怎么处理给别人的消息，是怎么说的？"*
   回答应该来自你的条目。新装的 MyOS 里还没有条目，先教它一点东西。

## 使用

照常和助手工作就行，不需要运行任何东西。MyOS 改变的是助手怎么判断，而不是它知道什么。下面这些是条目要求助手做的事；
助手仍可能漏用某条条目，或把它用在不合适的地方（见[探索地图](exploration-map.md#e08--proving-usefulness-rather-than-successful-machinery)）：

- 让它给正在和你有纠纷的人写信，它会站在你这边，并且在任何东西发出去之前先给你看草稿。
- 遇到卡住的问题，它会在常规做法旁边，给出你的方法所建议的做法。
- 你开始扩大一个项目的范围时，它会指出这是你的一个习惯。

条目只在对得上的地方才起作用，所以一个无关的编程问题应当不受影响。你当下说的话永远优先于
存下来的条目。MyOS 本身不能发送、付款或发布任何东西，助手自己的审批规则照样有效。

## 教它

MyOS 只向你学习，有三种方式：

| 你说 | 会发生什么 |
| --- | --- |
| 一次纠正：*"安排周末活动时，先给我看安静的选项。"* | 通过下面的检查后，存为 **candidate（候选）**，留下你的原话和出处。只用一行说明写了什么，以及现在有几条候选在等你，不提问。后来你又作出同类纠正时，它会在回答末尾问要不要采纳。 |
| *"记住这个"* 或 *"以后都这样"* | 存为 **adopted（已采纳）**：从此照着做。这句话就是批准，不再问一遍。 |
| 给它学习材料，比如一篇文章、你的笔记或一次过去的决定，并说明你认同哪些：*"读一下这篇，第 2、3 点就是我的想法。"* | 它只留下会改变你判断方式的部分，一条条目一个想法，带上出处。除非你认可，否则存为 **candidate（候选）**；想决定时说 *"过一遍我的候选"*。 |

### 什么能进来

MyOS 存的是判断，不是记忆。助手存任何东西之前都会检查四件事，四件都满足才行：

1. **它会改变以后的决定。** 在某一类你说得出来的情况下，它会改变助手的做法或建议。
   *"公司把它自己系统的错误算到我头上时，要顶回去"* 能进；*"我今天给保险公司打了电话"* 不能。
2. **它是长期的。** 发生过的事、对话摘要、任务进度、截止日期、会过时的事实，都不进来。
3. **它是你特有的。** 一个好助手本来就会这么做的，不存。*"要有礼貌"* 是所有人的默认；
   *"有纠纷时站在我这边"* 才是你的。
4. **它是新的。** 如果已经有条目讲了这个想法，助手会改进那条，比如补一个例外或一个例子，
   而不是再加一条。

不满足的不会存，助手会告诉你它该放在哪里：

| 这类东西 | 该放在 |
| --- | --- |
| 发生过什么、聊过什么 | 助手自己的记忆或聊天记录 |
| 待办的事、日期、to-do | 你的笔记或任务清单 |
| 某个项目怎么运作 | 那个项目自己的指令文件 |
| 文件、密钥、密码 | 原来的地方；MyOS 最多只留下其中的经验和一个链接 |

所以 *"记住我的航班 9 点起飞"* 该交给助手的记忆，而 *"记住：我宁可晚一班，也不要中转时间太紧"*
才进 MyOS。

### 候选与采纳

候选条目不会影响回答：在你采纳之前，它不会进入助手的指令。它留下你的原话，让后来的会话能识别重复。
想把一个想法先存着、以后再定，就说 *"先存为候选"*。每次存入候选或对候选作出决定后，那一行说明都会告诉你还剩几条在等（如果还有）。

候选会在两种时候交给你决定：

- **你又作出同类纠正。** 助手列出你的原话、日期和拟定的表述，让你选 **采纳 / 修改后采纳 / 仅此一次**。
- **你说 *"过一遍我的候选"*。** 助手按编号列出每条候选：你的原话、拟定的表述，以及现有条目是否已经涵盖它。
  你按编号回答：采纳、修改后采纳、仅此一次，或者继续等。

你的回复就是整个批准步骤：采纳后成为规则，有修改就用你的版本；选仅此一次就停用候选。
没回答则继续作为候选，本次会话不再问。退役的想法再出现时，从新的候选重新开始。
你也可以说 *"把关于 X 的那条去掉"*；历史仍然保留。

### 底线与核心

有两种改动需要你明确开口，因为以后每次会话都会受影响：**底线（boundary）**，也就是助手必须守住的限制；
以及 **核心（core）条目**，也就是在任何地方都全文显示的那不超过十条。说 *"把这条设为底线"* 或
*"把这条设为核心"*。候选的采纳流程不会创建或修改这两类条目。

已采纳的条目一改动，助手的指令就会自己刷新，新的会话会看到变化。

## 看看它存了什么

- 问助手：*"MyOS 里关于我怎么处理纠纷的是什么？"* 或者 *"列出我所有的底线。"*
- 想看全貌，在 `MyOS` 文件夹里运行 `poetry run myos view`，打开它给出的页面。条目按种类分组，
  核心条目在最前；每一条都能展开看正文、例子、出处和历史。

## 保持精简

模型越来越好，你的有些条目会变成好助手本来就会做的事。隔一段时间，比如新模型出来之后，让助手
*"跑一下 MyOS eval"*。它会用你自己的测试题各答三遍：不带 MyOS、把你的条目当成一份普通笔记、带 MyOS；再让另一个模型在不知道
哪份是哪份的情况下比较这些回答。每条条目会得到一个结论：仍然有用、模型已经会了、帮倒忙，或者还没测到。
你开口之前什么都不会改：模型已经会的可以退役，帮倒忙的要修改。

测试题放在你的 MyOS 文件夹里，和条目在一起。对实际回答的纠正，等你采纳条目时才附上测试题：
当时的请求，加上你想要的做法。候选阶段不加测试题。

## 它是怎么运作的

### 条目

你的自我模型由一组短条目组成。每条包含一个想法、它适用的情况、它的限制、一两个例子，
以及它的出处。它的种类告诉助手怎么用它：

| 种类 | 是什么 | 助手怎么用 |
| --- | --- | --- |
| 底线（boundary） | 助手替你做事时的限制 | 永远遵守。底线只能拦住一个动作，从不授权任何动作。 |
| 原则（principle） | 你怎么判断、怎么做事 | 默认照着做。 |
| 方法（method） | 你处理某类反复出现的事的办法 | 遇到那类事时使用。 |
| 模式（pattern） | 你的一个习惯 | 当它对你不利时指出来；从不把它当规则照做。 |
| 背景（context） | 关于你的事实和偏好 | 纳入考虑。 |

条目之间有冲突时：你当下说的话最优先，然后是底线，然后是原则和方法（适用范围更具体的那条胜出），
最后是模式。

只有 **adopted（已采纳）** 的条目才算规则。**candidate（候选）** 只在处理纠正、识别重复时，或你要求过一遍候选时读取，
不会用来回答请求。**uncertain（不确定）** 的条目当作建议来权衡，**reference（参考）** 条目当作证据。
**inactive（停用）** 的条目保留在视图和历史里，不进入目录。

### 一直在，还是用到时再读

助手对短的指令文件遵守得比长的好，Codex 和 Claude Code 也都建议把它写短。所以 MyOS
只往助手每次会话开始都会读的文件（`~/.codex/AGENTS.md` 和 `~/.claude/CLAUDE.md`）里
写一个紧凑的区块：

- 你的 **核心** 条目，全文；
- 其余每条已采纳的条目一行，写明什么时候适用。

任务对上了某一行，助手才去打开那条条目的全文。候选和其他未采纳的条目不进这个区块。

### 学习

普通纠正存为候选；已采纳的条目保持不变，对它的改进另存为候选，写明打算修改哪条。
当前任务按纠正处理；轮到你决定这条候选时，提问展示的是原条目的拟修改表述。你同意后才更新原条目，并停用单独的候选。
“记住这个”仍然直接采纳。指令区块只包含已采纳条目，随它们的改动刷新。
什么都不会被覆盖：每个旧版本都连同改动它的那句请求一起保留，
所以你能看到一条条目是怎么演变的，也能退回去。

### 你的数据

存储和本地产物位于你电脑上的私有文件夹中（默认 `~/.local/share/myos`），应放在代码仓库之外。
核心存储操作不调用模型；助手读取的条目会和你对话的其他内容一样，进入它所配置的模型服务。

可选的 `myos eval` 会启动 Claude Code 生成和评审回答。测试题、来源摘录、回答和自我模型上下文
可能发送给所配置的模型服务；运行前应检查选定测试题的内容。

### 哪些事留给助手

MyOS 不记录你的聊天，不替你执行任何动作，也不自带模型。理解和推理由助手完成，
MyOS 提供它应该运用的判断，目标是让这些判断在模型进步后仍然有用。这种提供方式是否比
包含相同内容的平铺笔记更有价值，计入维护成本后是否值得使用，仍需在实际使用中验证。
