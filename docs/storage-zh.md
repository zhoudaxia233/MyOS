# 认知记录长什么样

一条资产保存长期适用的个人判断，不是完整人格画像，也不保存持续事项的当前状态。新增条目遵循[用户指南的准入检查](getting-started-zh.md#什么能进来)。迁移记录可以保留历史字段，但这不表示新增条目也应保存这些内容。

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定标识。修正同一理解时继续使用它。 |
| `title` | 目录中的短标题。 |
| `content` | 长期适用的个人判断及其权衡；在文字中区分事实、个人表达和助手提炼。 |
| `applicability` | 什么情境下有用。 |
| `boundaries` | 不适用条件、例外、限制或反例。 |
| `status` | 下表中的一种状态。 |
| `basis` | 依据和不确定性说明，不是自动计算的可信度分数。 |
| `sources` | 非空来源引用列表，可附来源时间等信息。 |
| `type` | 宿主如何使用这条资产，见下表。除非状态是 `reference` 或 `inactive`，否则必填。 |
| `core` | 可选，`true` 或 `false`。核心资产在每次 `catalog` 调用时都返回全文，确保不会被漏掉；和其他资产一样，只在适用场景对得上时才应用。只有带类型的 `adopted` 资产可以是核心，同时最多 10 条，并且只能由所有者明确要求。 |
| `examples` | 可选，由 `{"text", "source"}` 组成的列表：这条资产的具体实例，每条都有自己的来源。 |

除 `core` 和 `examples` 外，这些都是 `put` 的必需字段（`type` 的例外见上）；额外字段可以保留。迁移记录还可能包含 `legacy_record`、历史采纳证据和时间不确定性说明，通常没有 `type`，在所有者审核前显示为 `unclassified`。模型不应只读一个状态标签就忽略这些条件。

### 类型告诉宿主怎么用

| 类型 | 使用含义 |
| --- | --- |
| `boundary` | 对 AI 替所有者做事的限制和条件。必须遵守，其他资产都不能覆盖；只能限制某个行动，永远不授予执行外部操作的权限。拿不准是否覆盖某个行动时，按适用处理。 |
| `principle` | 所有者怎么判断、怎么做事。默认照此执行；所有者当下明确的意图优先。 |
| `method` | 处理某类反复出现的任务时的思路或步骤。 |
| `pattern` | 所有者已知的倾向。用来理解和预判所有者，在它损害所有者自身利益时指出来；不是要遵守的规则，也不是要迎合的偏好。只描述行为，不做诊断。 |
| `context` | 关于所有者的事实、价值和稳定偏好。 |

资产冲突时，宿主依次采用：所有者当下明确的指示、`boundary`、`principle` 与 `method`（适用场景更具体的优先）、最后用 `pattern` 预判所有者，并指出不利于其自身利益的地方。

### 状态不是自动审批引擎

| 状态 | 使用含义 |
| --- | --- |
| `reference` | 保存为参考，不表示你已采纳。 |
| `candidate` | 未获采纳的想法，不用于回答。带出处的纠正例子，让后来的同类纠正能被识别为重复。 |
| `adopted` | 记录为已采纳的个人方法或理解；仍不是客观真理或行动授权。 |
| `uncertain` | 采纳、时间顺序或解释存在不确定性。 |
| `inactive` | 不进入默认目录，但当前记录与历史仍可按 ID 读取，也能在 `myos view` 中看到。 |

**除了 `inactive`，其他状态仍然进入 `catalog`。** `catalog` 返回 `{"core": [...], "index": [...]}`：核心资产带全文，其余非停用资产只列出 id、标题、类型、状态和适用场景。候选保留在索引里，让纠正能跨会话找到重复；回答时跳过它们，只有处理纠正时才读取匹配的候选。其他资产，包括核心，也只能按状态和依据在适用时使用。

第一次通过准入检查的普通纠正存为候选，`examples` 保留所有者原话，`sources` 保留出处和日期。后来同类纠正再出现时，补上另一个例子；宿主在回答末尾问是采纳、修改后采纳，还是仅此一次。回复授权写成 `adopted` 或 `inactive`。没回答则保留候选，本次会话不再问。“记住这个”或“以后都这样”直接授权采纳。存储会拒绝这些写入：把已采纳条目改成已采纳或已停用以外的任何状态、改动已停用条目的状态、在把条目改为已采纳的同一次写入里设置核心或改成底线类型、给未采纳条目附加测试用例；`myos check` 会报告旧历史里的同类转换。没有定时晋级、自动批准或物理删除命令。

改进已采纳的条目时，原条目保持不变，另存一条候选，`content` 写明原条目的 id 和标题；获批后为原条目写入新的已采纳版本，再停用候选。退役的想法再出现时，从新的候选重新开始，还需一次新的同类纠正才会提议。

### 磁盘上有什么

CLI 的 `--data` 优先于环境变量 `MYOS_DATA_DIR`；否则默认使用 `~/.local/share/myos`。MCP 使用其进程的 `MYOS_DATA_DIR`，没有 CLI 的 `--data` 参数。

```text
你选定的私有数据目录/
├── cognition.sqlite3       # 每个资产的完整修订、记录时间、授权记录，以及随写入保存的测试题
├── evals/                  # myos eval：cases/（可编辑的测试题文件）和 runs/
├── originals/              # 迁移复制的原始文件；全新手工写入不自动创建它
├── references.json         # 迁移源文件目录
└── migration.json          # 迁移清单、原始来源、摘要与导入修订核验信息
```

纠正产生的测试题只在条目被采纳时附上，因为 `myos eval` 不按条目状态筛选测试题。随写入保存的测试题，和对应的版本在同一个事务里存进数据库；每次写入之后、每次运行 `myos eval` 时，它会被导出到 `evals/cases/`。数据库保存提交时的原样，文件是 `myos eval` 读取的可编辑副本，所以以文件的修改为准。删掉文件，下次导出时会恢复提交时的版本；要停用一道题，在文件里写上 `"retired": true`。

只有首次授权写入或迁移才建立数据库。全新安装执行 `catalog` 返回 `{"core": [], "index": []}`，不会顺手创建存储；`myos view` 默认把 `myos-view.html` 写到这个目录，除非用 `--out` 指定其他路径；在数据库尚不存在时运行 `check --strict` 会报缺少存储，这不是“已经损坏”。

### 修订与并发

每次 `put` 都保存一个完整版本，不是 JSON 局部补丁。新增资产使用 `expected_revision: 0`；修改时使用刚读取的当前版本号。SQLite 事务会检查版本：另一位 agent 已先写入时，旧版本请求失败，而不是覆盖对方的更新。调用者应重新读取、整合，再决定是否写入，不能盲目重试旧内容。

旧版本、来源以及本次授权请求/来源一并保留。这里的 `recorded_at` 是写入时间，不能当成来源事件的发生时间。`inactive` 不删除历史；直接 `read ID` 仍能找到它。

### 来源展开的边界

迁移产生的 `originals/0/...jsonl#L2` 可以原样交给 `references`；`#L2` 表示从 1 开始的第二行。不带行号则返回整个文本文件。非法、越界行号和逃出 `originals/` 的路径被拒绝，符号链接也必须落在该目录内。

`put` 只保存引用，**不会下载文章或归档聊天正文**。普通消息 ID、网页地址或 `file:vault/...` 不是这个文件读取器支持的自动解析协议，应通过宿主已有且获授权的来源工具读取。需要长期保留的来源应有稳定的授权存放位置；当前工具没有通用附件归档 API，也不解析 PDF/图片。
